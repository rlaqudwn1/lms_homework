## Clarifications

### Session 2026-07-10

- Q: 행동 페르소나 5종 vs 아틀라스 아키타입 4종(넓이×깊이 2축)의 관계는? → A: **4종=표면, 5종=내부 레이어.** 랜딩·스냅샷 표면은 아키타입 4종만 노출. 행동 페르소나 5종(수집가·완주자·헌신형·잡식가·경쟁소셜형)은 분류 로직·신호 임계값 규칙의 내부 언어로 존속(R5-D 결정은 내부용으로 유지, 표면 노출 없음). "수집가"는 ICP(§3) 서술 언어로만 유지.
- Q: 아키타입 4종 네이밍 레지스터(O1 전반부)는? → A: **카토그래피(지도학) 레지스터 확정.** 목업 v3 매핑 유지 — 개척자 Explorer(넓+얕)·지도제작자 Cartographer(넓+깊)·정착자 Settler(좁+깊), 좁+얕 슬롯만 별도 확정. 근거 = 아틀라스 세계관 정합 + 탐험·개척 감정축(FR-012) + Slayer 레지스터는 Backlog Shuffle 선점(PRD §10 회피 가드).
- Q: 좁+얕 슬롯의 최종 명칭은? → A: **이 clarify에서 확정하지 않음 — 별도 조사 단계 필요.** 게이머 정체성 아키타입을 조사·운영해 온 레퍼런스(플레이어 타이폴로지 연구·실서비스 사례)를 리서치한 뒤 확정한다. v0 랜딩은 목업이므로 임시명 "산책자"를 그대로 사용하되 O1 잔여 항목으로 유지(동등-레지스터 톤 가드 FR-012·SC-004는 임시명에도 적용).
- Q: 데모 프로필 개수(O3)는? → A: **2개 확정 — 대비 포함.** 서로 다른 아키타입의 프로필 2종(예: 개척자 vs 정착자)을 전환해 볼 수 있게 해 "지도는 사람마다 다르다"를 눈으로 증명한다. 비용 = 하드코딩 데이터셋 1벌 추가.
- 참고(O2 — 질문하지 않음): 히어로 헤드라인 무게추는 R2에서 design과 CLOSED한 결정1=B의 재계량이므로 clarify 단독으로 확정·번복하지 않는다. **"design 재협의 필요" 플래그만 기록** — 확정은 `/handoff` 라운드에서(FR-011, Assumptions).

- Q: ② HOW IT WORKS 블록의 내용은? → A: **3단계 정적 설명.** "① Steam 공개 프로필 연결 → ② 플레이 신호 분석(플레이타임·도전과제) → ③ 당신의 아틀라스 완성"을 아이콘+한 줄 설명으로 제시. 인터랙션 없음, "실제 제품에서 이렇게 동작할 예정" 정직 표기(예시/데모 가드 정합, FR-015).
- Q: 장르 대륙 세트 규모는? → A: **목업 v3의 12개 세트 유지** — RPG·어드벤처·전략·퍼즐·액션·레이싱·시뮬레이션·메트로배니아·로그라이크·호러·FPS슈팅·대전격투. 3단계 상태(정복/탐험중/미개척)가 모두 분포. 두 번째 데모 프로필(O3)도 같은 12개 세트 위에 다른 채색만 입힌다(Key Entities).
- Q: 랜딩 카피 언어는? → A: **한국어 주 + 영문 포인트.** 본문·설명·모달 = 한국어, 헤드라인(R2 확정 영문)·아키타입 영문명·블록 타이틀 등 브랜드 요소 = 영문 허용. 목업 v3 관행과 동일(Assumptions).
- Q: SC의 "사용성 테스트 5명" 측정 장치의 지위는? → A: **문구 유지 + `[가정]` 태그.** 이 측정 장치는 spec 초안 생성 시 도입된 전제로 사용자가 정한 적 없음(clarify에서 확인). 테스트를 실시할 수도 있으므로 기준치는 유지하되, 실시 여부·시점 미정을 `[가정]`으로 표시. 미실시 시 비공식 관찰로 대체 판정(Success Criteria).

### Session 2026-07-10 (3차 · 커뮤니티 집중)

- Q: ⑤ COMMUNITY의 "게임별 예시 페이지"의 물리 형태는? → A: **랜딩 내 임베드 섹션.** ⑤ 블록 안에 게임 1종의 커뮤니티 페이지 목업을 프레임/카드로 임베드 — 별도 서브페이지 없음, 단일 정적 랜딩(FR-003) 유지. 실동작 페이지로 오인될 여지도 줄어 SC-003 정합(FR-009).
- Q: 커뮤니티 목업의 예시 게임 선정 기준은? → A: **추천 동선과 연결된 1종.** NEXT PICKS/지도 모달에 등장하는 예시 추천작 중 1종의 커뮤니티 페이지를 임베드 — "추천받은 게임 → 그 게임의 커뮤니티"로 서사 연결, 예시 데이터 재사용, 프로필 신호 인용으로 "너 기준 해석" 표식의 근거 성립(FR-009).
- Q: "coming soon" 예고 목록의 범위는? → A: **아틀라스 스냅샷 공유까지 포함.** 예고 목록 = ① "너 같은 사람들" ② 유저 카운트 ③ 아틀라스 스냅샷 공유. 스냅샷은 IDENTITY 블록에서 개념으로 보여주고 공유 버튼 자리에 coming soon 표식 — 실배관 0줄 유지(헌법 III 정합), 공유 갈증 관찰은 §6.5 $0 게이트의 예비 신호(FR-009, Key Entities).
- Q: 커뮤니티 임베드의 객관 숫자 지표 세트는? → A: **3지표 — ① 평균 플레이시간(HLTB 모사) ② 글로벌 완주율(메인 스토리 도전과제 달성%) ③ 대표 도전과제 2~3개의 글로벌 달성률.** 셋 다 game-level 공개 통계로 game≠player 가드(부록 A) 준수, 그 위에 "너 기준 해석" 한 줄이 별도 표식으로 얹힘(FR-009, Assumptions).
- Q: 별점·리뷰 UI의 목업 표현 수위는? → A: **접힌 보조 영역으로 표현.** 숫자 3지표가 상단에 크게, 그 아래 "의견 레이어"는 접힌/작은 보조 영역으로 예시 리뷰 1~2줄 + 별점 표시 — "숫자 우선, 의견은 선택"의 위계를 레이아웃 자체로 전달(FR-010).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방문자가 "이게 뭘 하는 제품인지"를 아틀라스 체험으로 이해 (Priority: P1)

처음 방문한 사람이 랜딩에 도착해, 예시 프로필로 그려진 **취향 지도**(장르 대륙이 플레이타임으로 3단계 채색)와 **판정된 아키타입**을 보고, 대륙/섬을 클릭해 "왜 이 게임을 다음에" 설명 모달을 열어본다. 그 흐름만으로 "내 스팀 취향을 지도로 보여주고 다음 게임을 근거와 함께 추천하는 서비스"임을 이해한다.

**Why this priority**: 랜딩의 1차 목적 = 아이디어 소개. 이 체험 하나만 있어도 제품 컨셉이 전달되는 최소 가치 슬라이스(MVP)다. 나머지 블록은 이 핵심 payoff를 보강할 뿐이다.

**Independent Test**: 다른 블록(커뮤니티) 없이 아틀라스 섹션만 배포해도, 방문자가 지도 인터랙션 → 아키타입 → 설명 모달을 끝까지 돌려보고 컨셉을 말로 설명할 수 있으면 통과.

**Acceptance Scenarios**:

1. **Given** 방문자가 랜딩 히어로에 도착, **When** 아래로 스크롤해 취향 지도 섹션에 닿으면, **Then** 예시 프로필의 장르 대륙 지도가 3단계 채색(미개척/탐험중/정복)으로 렌더되고 판정된 아키타입이 표시된다.
2. **Given** 취향 지도가 보이는 상태, **When** 방문자가 정복/탐험 상태의 대륙을 클릭하면, **Then** 그 장르의 추천 게임 + 신호에 접지된 "왜"(예시 플레이 이력 인용) + 클리어 소요시간 + 진행 CTA가 담긴 모달이 열린다.
3. **Given** 인접성이 약한 완전 미개척 대륙, **When** 방문자가 그것을 클릭하면, **Then** 억지 추천 대신 "지금은 권하지 않는다"는 정직한 안내가 표시된다.
4. **Given** 랜딩의 모든 데이터는 예시, **When** 방문자가 어떤 숫자·스냅샷을 보든, **Then** 그것이 실제 본인 데이터가 아니라 "예시/데모"임을 알 수 있는 표식이 함께 보인다.

### User Story 2 - 방문자가 커뮤니티·공유(전략적 해자)를 예고편으로 만난다 (Priority: P2)

방문자가 게임별 커뮤니티 예시 페이지에서 객관 숫자(게임단위 평균 시간·글로벌 도전과제%)가 크게 서고 그 위에 "너 기준 해석"이 별도 표식으로 곁들여지는 것을 보며, "숫자 우선" 포지셔닝과 함께 **이 제품이 지향하는 표현·공유 커뮤니티(해자)**를 예고편으로 체감한다. "너 같은 사람들" 같은 유저베이스 기반 기능은 "coming soon"으로 정직하게 표시된다.

**Why this priority**: 커뮤니티·공유 루프는 이 제품의 **전략적 심장이자 최종 해자**(PRD §4). v0 빌드에선 만들지 않지만(커뮤니티=0), 랜딩은 이걸 "유저베이스 후 열릴 해자"로 **예고**한다 — 없어도 되는 보강이 아니라 제품 서사의 핵심을 소개하는 블록. 단 P1(아틀라스 체험)이 컨셉 전달의 MVP이므로 순서상 P2.

**Independent Test**: 커뮤니티 예시 페이지 단독으로, ① 객관 숫자와 개인화 해석 표식이 시각적으로 구분되고 ② 유저베이스 필요 기능이 "coming soon"으로 정직하게 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 게임별 예시 페이지, **When** 방문자가 지표를 보면, **Then** 객관 숫자가 크게, 개인화 해석은 눈에 띄는 별도 표식으로 함께 존재한다.
2. **Given** 리뷰/의견 요소, **When** 방문자가 보면, **Then** "숫자 우선, 의견은 선택 레이어" 포지셔닝이 드러나고(별점은 부가), 무근거 우월 카피("별점 다툼 없음" 류)는 없다.
3. **Given** "너 같은 사람들"·유저 카운트 등 유저베이스 필요 요소, **When** 방문자가 보면, **Then** "coming soon"(B단계) 표식으로 정직하게 예고되며 실제 데이터인 척하지 않는다.

### Edge Cases

- 방문자가 지도의 **미개척(0시간) 대륙**을 클릭하면? → 억지 추천 금지, "지금은 권하지 않음" 정직 안내(US1-3).
- 방문자가 데모 데이터를 **자기 실제 데이터로 오인**하면? → 모든 표면에 "예시/데모" 표식 필수(US1-4).
- **모바일 좁은 화면**에서 대륙 지도가 깨지거나 라벨이 겹치면? → 지도·라벨·모달이 반응형으로 유지되어야 함.
- 아키타입 **좁+얕 사분면**(현재 임시명 "산책자")이 다른 세 사분면과 **다른 위계로 읽히면**(우열 함의 발생)? → 네 사분면 동등 레지스터 유지, 최종 명칭은 O1에서 확정.
- 방문자가 모달을 **연속으로 여러 대륙** 클릭하면? → 이전 모달이 닫히고 새 대륙 내용으로 매끄럽게 전환.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 랜딩은 **5블록 IA**를 순서대로 제시해야 한다 — ① HERO → ② HOW IT WORKS → ③ IDENTITY(취향 아틀라스) → ④ NEXT PICKS → ⑤ COMMUNITY.
- **FR-002**: 모든 표시 데이터는 **하드코딩 예시**여야 하며, 실제 사용자 데이터인 것처럼 보이지 않도록 각 표면에 **"예시/데모" 표식**을 동반해야 한다.
- **FR-003**: 랜딩은 **가입·로그인·설치·실 백엔드·Steam 연동 없이** 정적 자산만으로 동작해야 한다.
- **FR-004**: IDENTITY 블록은 **장르 대륙 지도**를 렌더하고, 각 대륙을 플레이타임 기반 **3단계**(미개척 / 탐험중 / 정복)로 채색해야 한다.
- **FR-005**: IDENTITY 블록은 예시 신호로부터 **아키타입 1종을 판정**해 표시해야 한다(2축 = 넓이 × 깊이, 4종 세트). **아키타입 4종 = 표면 유일 체계**(2026-07-10 확정) — R5-D 행동 페르소나 5종은 분류 로직·신호 임계값의 내부 언어로만 존속하며 랜딩 표면에 노출하지 않는다.
- **FR-006**: 방문자는 대륙/섬/프론티어를 **클릭**할 수 있어야 하며, 클릭 시 추천 게임 + **신호에 접지된 "왜"** + 클리어 소요시간 + 진행 CTA를 담은 **설명 모달**이 열려야 한다.
- **FR-007**: 추천 근거("왜")는 **예시 플레이 이력의 신호를 인용**해야 하며, 신호가 뒷받침하지 않는 주장을 지어내지 않아야 한다(설명 극장 금지).
- **FR-008**: 인접성이 약한 **완전 미개척 장르**에 대해서는 억지 추천 대신 **"지금은 권하지 않음"** 정직 안내를 제공해야 한다.
- **FR-009**: COMMUNITY 예시는 **랜딩 내 임베드 섹션**(⑤ 블록 안에 게임 1종의 커뮤니티 페이지 목업을 프레임/카드로 임베드, 별도 서브페이지 없음 — 2026-07-10 3차 clarify)으로 제시하며, 예시 게임은 **NEXT PICKS/지도 모달의 추천작 중 1종**으로 선정해 추천 동선과 서사를 잇는다. **객관 숫자를 크게**, 그 위에 **개인화 해석을 눈에 띄는 별도 표식**으로 함께 제시해야 한다. 커뮤니티·공유는 이 제품의 전략적 해자(PRD §4)이므로, **coming soon 예고 목록 = ① "너 같은 사람들" ② 유저 카운트 ③ 아틀라스 스냅샷 공유**(B단계)로 "미룬 심장"임을 드러내되 v0에선 빌드하지 않는다. 스냅샷 공유 예고는 IDENTITY 블록의 공유 버튼 자리에 표식으로 둔다(실배관 0줄).
- **FR-010**: 포지셔닝 카피는 **"숫자 우선, 의견은 선택 레이어"**를 따르고, 별점/리뷰는 **접힌/작은 보조 영역**(예시 리뷰 1~2줄 + 별점, v0 실기능 아님 — 2026-07-10 3차 clarify)으로만 표현해 위계를 레이아웃으로 전달하며, 무근거 우월 카피를 포함하지 않아야 한다.
- **FR-011**: 히어로 헤드라인은 **백로그 유틸리티 우선**(결정1=B) 톤을 기본으로 하되, 정체성 vs 추천의 헤드라인 무게추는 O2 확정에 따른다. ⚠️ O2 = R2에서 design과 CLOSED한 결정의 재계량 → **design 재협의 필요 플래그**, 확정은 `/handoff` 라운드에서(clarify 단독 번복 금지).
- **FR-012**: 아키타입·톤은 **탐험·개척** 감정축을 일관되게 쓰고, 네 사분면을 **동등한 레지스터로 서술**해야 한다(어느 사분면도 우열·결핍으로 프레이밍하지 않음). 경쟁사(Backlog Shuffle)의 죄책감·낭비액 프레임과 차별화.
- **FR-013**: 랜딩은 **반응형**이어야 하며, 좁은 화면에서도 지도·라벨·모달이 깨지지 않아야 한다.
- **FR-014**: NEXT PICKS 블록(④)은 현재 활성 데모 프로필의 지도에서 도출된 **"다음 행선지" 추천 카드 2~3장**을 제시해야 한다 — 각 카드 = 게임명 + 신호접지 "왜" 한 줄 + 클리어 소요시간. 모달(FR-006)과 동일한 예시 추천 데이터를 재사용하며, 데모 프로필 전환 시 카드도 함께 갱신된다.
- **FR-015**: HOW IT WORKS 블록(②)은 **3단계 정적 설명**을 제시해야 한다 — ① Steam 공개 프로필 연결 → ② 플레이 신호 분석(플레이타임·도전과제) → ③ 당신의 아틀라스 완성. 인터랙션 없이 아이콘+한 줄 설명으로 구성하며, 실 연결 기능이 없는 v0에서는 "실제 제품에서 이렇게 동작할 예정"임을 정직하게 표기한다(FR-002·FR-003 정합).

### Key Entities *(include if feature involves data)*

- **예시 프로필(Demo Profile)**: 하나의 가상 스팀 사용자. 속성 = 장르별 플레이타임 벡터, 판정된 아키타입, 백로그 예시. **2개 확정(2026-07-10 clarify, O3 종결)** — 서로 다른 아키타입 대비(예: 개척자 vs 정착자)로 "지도는 사람마다 다르다"를 증명, 방문자가 전환해 볼 수 있어야 한다.
- **장르 대륙(Genre Continent/Island)**: 하드 카테고리 장르 1개. 속성 = 이름, 플레이타임 강도(0~1), 상태(미개척/탐험중/정복), 프론티어 여부, 연결된 추천 게임. **세트 = 목업 v3의 12개 확정(2026-07-10 clarify)** — RPG·어드벤처·전략·퍼즐·액션·레이싱·시뮬레이션·메트로배니아·로그라이크·호러·FPS슈팅·대전격투. 두 데모 프로필은 같은 세트 위에 채색만 다르다.
- **아키타입(Archetype)**: 넓이×깊이 2축 4종 중 하나. 속성 = 한글명·영문명·축 라벨·설명·포트레이트(현재 SVG placeholder). 좁+얕 명칭은 임시("산책자"), O1 확정 대기. 표면 유일 체계 — R5-D 행동 페르소나 5종은 내부 분류 레이어로만 존속(FR-005, Clarifications 2026-07-10).
- **추천 게임(Next Pick)**: 대륙에 연결된 예시 추천. 속성 = 게임명, 신호접지 "왜" 문장, 클리어 소요시간, 진행 CTA 라벨.
- **아틀라스 스냅샷(Atlas Snapshot)**: 취향 아틀라스를 공유용으로 정적 렌더한 이미지(= 옛 "정체성 카드"의 재정의). v0 랜딩은 개념 표현까지만 — 공유·내보내기 배관은 컷(PRD §7), 공유 가설 검증은 §6.5 $0 게이트(별도). **공유 버튼 자리에 "coming soon" 표식**으로 예고(2026-07-10 3차 clarify, FR-009).

## Assumptions

- **배포 형태**: Vercel 등 정적 호스팅에 배포되는 단일 랜딩(멀티 유저·세션 없음). 데모 프로필은 사전 준비된 하드코딩 데이터.
- **대상 방문자**: 아이디어를 소개받을 지인·부트캠프/커뮤니티 관람자. 일반 대중 대상 마케팅 랜딩이 아님. (팀원 모집 목적은 이번 스코프에서 삭제.)
- **카피 언어 = 한국어 주 + 영문 포인트(2026-07-10 clarify)**: 본문·설명·모달은 한국어, 헤드라인(R2 영문 확정)·아키타입 영문명·블록 타이틀 등 브랜드 요소는 영문 허용. 이중 언어 토글은 스코프 밖.
- **O1(아키타입 네이밍) = 절반 확정(2026-07-10 clarify)**: 레지스터 = **카토그래피 확정**(개척자/지도제작자/정착자 유지). 좁+얕 슬롯 이름은 **별도 조사 단계 후 확정** — 게이머 정체성 아키타입 레퍼런스(플레이어 타이폴로지 연구·실서비스 운영 사례) 리서치 필요. v0 목업은 임시명 "산책자" 사용(Clarifications).
- **O2(헤드라인 무게추) = design 재협의 대기**: 히어로가 정체성-서사 우선인지 백로그-유틸 우선인지의 최종 무게추는 열림. 기본값 = R2 결정1=B(백로그 유틸 우선 헤드라인). R2 CLOSED 결정의 재계량이므로 clarify에서 확정하지 않음 — `/handoff` 라운드에서 design과 재협의 후 확정(FR-011).
- **아키타입 포트레이트**: 현재 인라인 SVG placeholder("ART TBD"). 실제 캐릭터 이미지(이모지 금지)는 후속 아트 작업.
- **커뮤니티 예시 데이터**: 게임단위 공개 통계를 모사한 하드코딩 값. **지표 세트 = 3종 확정(2026-07-10 3차 clarify)** — 평균 플레이시간(HLTB 모사)·글로벌 완주율·대표 도전과제 2~3개 달성률. 전부 game-level 통계로 game≠player 가드 준수. "너 같은 사람들"·우리 유저 카운트 등 유저베이스 필요 지표는 v0 밖(B단계).
- **실 ML 코어·Steam 연동·로그인**: 이 스펙 밖. 별도 스펙 + 신호 충분성 게이트 PASS 후.
- **컨셉 목업 v3 존재**: `next-save-taste-atlas.html`이 시각 참조 기준선. 이 스펙은 그것을 5블록 랜딩으로 공식화·확장한다.
- **페르소나 체계 = 확정(2026-07-10 clarify)**: 아키타입 4종 = 표면 유일 체계, R5-D 행동 페르소나 5종 = 분류 로직·신호 임계값의 내부 레이어로만 존속(랜딩 표면 노출 없음). "수집가"는 ICP 서술 언어로만 유지(FR-005, Clarifications).
- **커뮤니티 = 의도적으로 미룬 전략 해자**: 커뮤니티·공유 루프는 제품의 전략적 심장(PRD §4)이나 v0 빌드=0. 랜딩은 이를 "coming soon"(B단계)으로 예고할 뿐 실빌드하지 않는다(FR-009).
- **공유·내보내기 배관 = v0 컷**: 아틀라스 스냅샷의 실제 공유 기능은 v0 밖(PRD §7). 공유 가설은 §6.5 $0 게이트로 별도 검증.
- **design과의 정합 = 원장 동기화 대기**: 이 스펙의 아틀라스·커뮤니티 서사는 아직 `handoff/next-save.md` 원장·design 랩(`../design`)에 미반영. `/handoff`로 별도 라운드 필요.
