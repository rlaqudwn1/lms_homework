# 장르→코어 매핑 조사 (M2) — Steam 태그 접지 + 12대륙 × 5코어

> **정체:** NEXT SAVE 태스크 **M2**(`SIG` 신호 엔진 도메인) 산출물. 12개 장르 대륙이 소프트 코어 5종 중 어디에 신호를 주는지 매핑하고, 경쟁/협동 태그 분리 기준을 Steam 실태그로 정의한다.
> **날짜:** 2026-07-20 · **상태:** 조사 완료 〔조사→분석〕 — **임계값·배정 규칙은 전부 잠정.** 최종 확정은 M1(공개 Steam 프로필 5~8개 실투입) 실측 후.
> **사용처:** ① MAP 아틀라스 지도 채색 근거 ② ARC 아키타입 판정(특히 경쟁소셜형 복합신호) 근거 ③ M1 프로필 실측의 입력.
>
> **저맥락 요약 (이 문서만 읽는 사람용):** NEXT SAVE는 Steam 플레이 이력을 "취향 아틀라스"(장르 대륙 지도 + 게이머 아키타입)로 보여주는 서비스다. 아키타입은 하드 라벨 1개가 아니라 **소프트 코어 5종**(완주자·잡식가·수집가·헌신형·경쟁소셜형 — 주 코어 + 강도% + 보조 태그 + 개인 근거)으로 판정하며, 판정에는 player-level 신호 5종을 쓴다: **S1** 게임별 플레이타임 · **S2** 본인 도전과제 달성% 중앙값 · **S3** 장르 집중도(시간가중) · **S4** 멀티플레이 시간 비중 · **S5** 백로그율(0시간 보유 비율). 장르 대륙은 12개 확정 세트: RPG · 어드벤처 · 전략 · 퍼즐 · 액션 · 레이싱 · 시뮬레이션 · 메트로배니아 · 로그라이크 · 호러 · FPS슈팅 · 대전격투.
>
> **가드 2종 (문서 전체에 적용):**
> 1. **game-level ≠ player-level.** 이 문서의 장르 단위 서술(게임 수·달성 설계 경향 등)은 신호의 *해석 맥락*이자 매핑 근거일 뿐, 플레이어 판정 임계값으로 직접 쓰지 않는다. 플레이어 판정은 언제나 본인 신호(S1~S5)로만.
> 2. **동등 레지스터.** 다섯 코어는 서로 다른 탐험 스타일이며 우열이 없다. "강/중/약/무"는 *그 장르가 해당 코어 판정에 주는 신호의 변별력*이지, 코어나 장르의 가치 평가가 아니다.

## §1 Steam 태그 taxonomy 요약

### 1.1 삼중 구조 — 장르 정보가 세 레이어에 나뉘어 있다 [검증]

|---|---|---|---|
| **① 공식 genre 필드** | 개발자 선택 (appdetails API `genres`) | 게임용 장르 ~12종의 고정 리스트: Action(1)·Strategy(2)·RPG(3)·Casual(4)·Racing(9)·Sports(18)·Indie(23)·Adventure(25)·Simulation(28)·Massively Multiplayer(29)·Free to Play(37)·Early Access(70) | 굵은 1차 분류. **퍼즐·호러·FPS·격투·메트로배니아·로그라이크는 여기 없음** |

핵심 함의: **12대륙은 레이어 ①과 ②를 가로지른다.** 6개 대륙(RPG·어드벤처·전략·액션·레이싱·시뮬레이션)은 공식 genre 필드와 1:1 대응이 있고, 나머지 6개(퍼즐·메트로배니아·로그라이크·호러·FPS슈팅·대전격투)는 유저 태그로만 조작화된다. [검증 — genre 필드 리스트 및 태그 목록 대조]

또한 태그 위계가 균일하지 않다: 서드파티 집계(SRec, Steamworks 문서 분류 기반)에서 **Roguelike는 "Genre" 층, Horror·FPS·Metroidvania는 "Sub Genre" 층, Puzzle은 "Top Genre" 층**으로 분류된다 — 대륙마다 앵커 태그의 "행정 등급"이 다르다는 뜻이며, 조작화는 등급이 아니라 태그 이름 기준으로 하면 문제없다. [검증 — SRec 분류표]

## §2 장르×코어 매핑표 (12대륙 × 5코어)

### 2.0 열 읽기 가이드 — 먼저 읽을 것

등급의 뜻: **그 대륙에 시간이 쏠려 있다는 사실이 해당 코어 판정에 주는 변별력.** 강 = 코어 판정의 직접 증거/맥락, 중 = 위성 분기나 다른 신호와 결합 시 유효, 약 = 보조 맥락 수준, 무 = 판정에 정보 없음.

구조적 발견(이 표의 요지): **5코어의 장르 의존성이 3계층으로 갈린다.**
- **장르 의존 코어 (2):** 헌신형·경쟁소셜형 — 어떤 대륙에 시간이 쏠렸는지가 판정 재료 그 자체.
- **장르 = 해석 보정 코어 (1):** 완주자 — 판정은 S2(본인 달성% 중앙값)로 하되, 대륙별 달성 설계 경향이 **보정 맥락**(같은 S2 40%라도 로그라이크 중심 유저와 어드벤처 중심 유저는 의미가 다름).
- **장르 비의존 코어 (2):** 잡식가(S3 *분산*이 신호 — 개별 대륙은 전부 "무", 가짓수로만 기여)·수집가(S5는 라이브러리 전체 속성). 이 두 열이 비어 보이는 것은 결함이 아니라 **신호 직교성이 확보된다는 좋은 소식**이다 — 장르 축이 5코어를 서로 겹치지 않게 돕는다.

### 2.2 매핑에서 특기할 점 (분석 메모)

1. **경쟁소셜형 "강"은 정확히 2곳** — 대전격투, FPS슈팅. 그리고 FPS조차 위성 분기(경쟁 위성 vs 캠페인 위성) 없이는 못 쓴다. → 경쟁소셜형이 왜 복합신호(S4×태그)여야 하는지를 매핑표가 재확인.
2. **헌신형 "강" 3곳(RPG·시뮬레이션·FPS)은 서로 성격이 다르다** — RPG·시뮬은 솔로 장기 몰입, FPS는 경쟁 반복. **헌신형(강)과 경쟁소셜형(강)이 FPS에서 겹친다** → 두 코어의 판별은 장르가 아니라 S4로 해야 함(장르만으로는 CS류 천시간 유저가 두 코어 모두에 걸림). S1 vs S3 귀속 문제(M1 게이트 ①)와 함께 볼 것.
3. **완주자의 진짜 산출물은 "보정표"다** — 어드벤처·메트로배니아(달성 소진이 자연스러운 대륙)와 로그라이크·대전격투(달성 소진이 초장기전인 대륙)의 S2를 같은 잣대로 읽으면 안 된다. v0에서 보정 산식까지 갈 필요는 없고, **근거 문장에 대륙 맥락을 한 줄 곁들이는 것**부터(예: "로그라이크 중심 라이브러리 기준으로는 높은 달성률") `[미정: 보정 방식]`.
4. **잡식가·수집가 열이 "무"로 도배된 것은 설계 검증** — 이 두 코어는 장르 축과 직교. 다만 잡식가의 장르 *카운트*는 우산 태그 왜곡을 받으므로 §5의 배정 사다리가 선행돼야 한다.
5. **로그라이크는 S2 왜곡의 대표 사례 대륙** — "S2 낮음 = 완주 성향 낮음"이라는 직독을 막는 반례 공급원. 근거 발화 규칙(R1)에 대륙 보정 문구를 붙일 근거.

## §3 경쟁/협동 태그 분리 기준 + 경쟁소셜형 복합신호 조작화

### 3.1 왜 S4 단독으로는 안 되나 (재확인)

S4(멀티플레이 시간 비중)는 경쟁(PvP)과 협동(Co-op)을 구분하지 못한다. 코옵 파밍·협동 생존 크래프트에 시간을 쏟는 유저와 랭크 대전에 시간을 쏟는 유저는 같은 S4 값을 가질 수 있다. 문헌 평균 멀티 비중 57.7%(player-typology §4)를 감안하면 멀티 시간 자체는 흔한 속성이라 변별력이 낮다. → **경쟁소셜형 = S4 × 경쟁 판별의 복합신호**여야 한다.

### 3.2 판별 재료 — Steam이 이미 제공하는 이분법 [검증]

**레이어 ③ 스토어 카테고리(개발자 선언, 이진 플래그)가 1차 축이다.** Steam은 PvP군과 Co-op군을 별도 카테고리로 운영한다:

| 군 | 카테고리 (ID) | 게임 수 (stmstat, 2026-07) |
|---|---|---|
| **PvP군** | PvP(49) · Online PvP(36) · LAN PvP(47) · Shared/Split Screen PvP(37) | PvP 34,286 · Online PvP 29,371 |
| **Co-op군** | Co-op(9) · Online Co-op(38) · LAN Co-op(48) · Shared/Split Screen Co-op(39) | Co-op 42,478 · Online Co-op 29,426 |
| **중립** | Multi-player(1) · MMO(20) · Cross-Platform Multiplayer(27) · Shared/Split Screen(24) | Multi-player 64,780 · MMO 4,698 |

카테고리가 태그보다 신뢰도가 높은 이유: 개발자가 스토어 기능 표기로 직접 선언하는 이진값이라 커뮤니티 태깅 편차가 없다. 단, PvP/Co-op 세분 카테고리는 후기에 추가된 체계라 구작에는 미선언일 수 있다 `[가정]` → 태그 폴백(3.3)으로 보완.

**레이어 ② 유저 태그가 2차 축(폴백 + 강도 판별)이다.** 아래 목록은 전부 실존 태그로 확인됨 [검증 — store.steampowered.com/tag/browse/ 대조]:

- **경쟁 확정 태그 (장르 정의상 PvP):** Fighting · 2D Fighter · 3D Fighter · MOBA · Battle Royale · Hero Shooter · Extraction Shooter · Arena Shooter · Auto Battler · Combat Racing · eSports
- **경쟁 성향 태그 (보조):** PvP · Competitive · Social Deduction `[가정: 포함 여부]`
- **협동 태그:** Co-op · Online Co-Op · Local Co-Op · Co-op Campaign · 4 Player Local · PvE · Massively Multiplayer · MMORPG `[가정: MMORPG는 PvE 우세로 간주]`
- **중립 태그 (판별에 쓰지 않음):** Multiplayer · Local Multiplayer · Cross-Platform Multiplayer · Asynchronous Multiplayer · Party Game · Team-Based (Team-Based는 경쟁·협동 양쪽에 걸림)

### 3.3 제안 규칙 — 게임 단위 라벨 → 시간 가중 집계 (전부 `[가정]`, M1 튜닝 대상)

**1단계: 게임 g를 4클래스로 라벨링**

```
has_pvp  = g의 카테고리 ∩ PvP군 ≠ ∅
has_coop = g의 카테고리 ∩ Co-op군 ≠ ∅
comp_tag = g의 상위 20 태그 ∩ (경쟁 확정 ∪ 경쟁 성향) ≠ ∅
coop_tag = g의 상위 20 태그 ∩ 협동 태그 ≠ ∅

if has_pvp and not has_coop        → MULTI_COMP   (경쟁 멀티)
elif has_coop and not has_pvp      → MULTI_COOP   (협동 멀티)
elif has_pvp and has_coop:
    경쟁 확정 태그 히트 and not coop_tag → MULTI_COMP
    coop_tag and not comp_tag           → MULTI_COOP
    그 외                               → MULTI_MIXED
elif Multi-player or MMO 카테고리만 → 태그로 재판별, 실패 시 MULTI_MIXED
else                                → SOLO
```

**2단계: S4를 셋으로 분해 (시간 가중)**

```
S4_comp  = Σ시간(MULTI_COMP)  / 총시간
S4_coop  = Σ시간(MULTI_COOP)  / 총시간
S4_mixed = Σ시간(MULTI_MIXED) / 총시간
(기존 S4 ≈ S4_comp + S4_coop + S4_mixed)
```

**3단계: 경쟁소셜형 복합신호**

- 판정 신호 = **S4_comp** (+ S4_mixed의 산입 비율 `[미정: 0 / 0.5 / 태그 재판별]`)
- 잠정 임계값 `[가정]`: **S4_comp ≥ 35~40%** — 기존 시트 §2의 "멀티 비중 ≥55%"는 S4 *전체* 기준이었으므로, 경쟁분만 세는 새 신호에서는 하향이 필요하다. 수치는 M1 실측에서 튜닝.
- 근거 발화에는 반드시 분해값을 인용: "네 멀티 시간의 대부분이 **대전(PvP) 게임**에 있어(S4_comp {값}%)" — 협동 멀티 유저를 경쟁형으로 서술하는 오류를 구조적으로 차단.

### 3.4 엣지 케이스 가드

| 케이스 | 문제 | 처리 제안 |
|---|---|---|
| **F2P 경쟁 대작** (MOBA·BR·히어로슈터 다수) | 무료 게임이라 수집 API에서 누락 가능 + S5 백로그율 분모 왜곡 | `GetOwnedGames(include_played_free_games)` 필수(시트 §1 기존 방침과 일치). S5 분모에서 F2P 처리 `[미정]` |
| **캠페인+멀티 하이브리드** | 공개 데이터에 모드별 플레이타임이 없어 한 게임 안의 시간 분해 불가 | MULTI_MIXED 클래스가 흡수 — 게임 단위 라벨링의 구조적 한계로 명시 |
| **비대칭 대전 호러(4v1)** | 장르는 호러인데 실플레이는 PvP | 카테고리 PvP군 선언이 있으므로 규칙이 자동으로 MULTI_COMP 처리 — 호러 대륙의 "예외 위성" (§2 표) |
| **이름 함정** | Spectacle fighter·Beat 'em up은 "fighter" 계열 이름이지만 비대전 솔로/협동 액션 | 경쟁 태그 리스트에 **불포함** (§3.2 목록이 이미 반영) |
| **구작 카테고리 미선언** | PvP/Co-op 세분 플래그 부재 가능 | 태그 폴백 경로가 커버, MIXED 비율 모니터링 |
| **MMO** | PvP·PvE 혼재 | MMO 카테고리 단독으로는 판별하지 않고 태그로 재판별, 실패 시 MIXED |

## §4 5→6 코어 분리(경쟁형 ↔ 협동소셜형) 관련 근거 정리

> **판정 유보.** 이 절은 양방향 근거의 정리이며 결론을 내리지 않는다. 최종 판정 = **M1 프로필 실측**(게이트 ②)에서.

### 4.1 분리를 지지하는 근거

1. **플랫폼 데이터가 이미 이분을 제공한다 [검증]** — Steam 카테고리 체계 자체가 PvP군/Co-op군을 별도 플래그로 운영(§3.2). 조작화 비용이 낮고, S4_comp/S4_coop 분해는 어차피 §3 규칙의 부산물로 공짜로 얻는다.
2. **두 모집단 모두 대형이다 [검증·서드파티]** — 카테고리 기준 PvP 34,286개 vs Co-op 42,478개(겹침 존재). 협동이 경쟁의 부속이 아니라 대등 규모의 독립 생태계.
3. **동기 연구가 반복적으로 두 축을 가른다 [검증 — player-typology.md 경유]** — Quantic Foundry 12동기에서 Competition과 Community는 별개 동기, Trojan Player Typology(행동 검증된 유일 프레임워크)도 Competitor와 Socializer를 별도 유형으로, Bartle도 Killer와 Socialiser를 별도 사분면으로 둔다. "함께 노는 것"과 "겨루는 것"은 문헌상 일관되게 다른 동기다.
4. **매핑표가 두 코어에 서로 다른 장르 프로필을 줄 수 있다** — 경쟁 신호 원천(대전격투·FPS 경쟁 위성·전략 래더 위성)과 협동 신호 원천(시뮬 코옵 위성·MMORPG PvE·협동 생존 크래프트)이 대륙 지도상 뚜렷이 갈린다(§2). 갈라도 각자 설 자리가 있다.

### 4.2 하나로 유지를 지지하는 근거

1. **신호 원천이 하나다** — 두 코어 모두 S4의 분해값에서 나온다. 신호 1개에서 코어 2개를 파생하면 신호 직교성(GPT 검증항목 "축 중복성·신호 분리도")이 다시 나빠진다. S3가 여러 코어를 동시에 먹이는 기존 문제(시트 §2.5 열린 항목 2)를 S4에서 재생산하는 셈.
2. **MIXED 비중이 미지수다** — PvP·Co-op 카테고리를 동시 선언한 게임이 많을수록(대형 멀티 타이틀에 흔한 패턴 `[가정]`) 게임 단위 분해의 해상도가 떨어지고, 분리해 봤자 두 코어의 실측 구분력이 낮을 수 있다.
3. **협동소셜형 전용 확증 신호가 공개 프로필 밖이다** — "누구와 함께 플레이하는가"(친구 동시 접속, 파티 이력)는 공개 프로필/기본 API로 안 잡힌다. 코어 하나를 세우기엔 S4_coop 하나뿐이라 신호 기반이 얇다.
4. **표면 서사 단순성** — 5코어는 아틀라스 표면(레이더·스냅샷)의 서사 단위이기도 하다. 이는 제품 판단이지 데이터 근거는 아니므로 참고로만 `[가정]`.

### 4.3 M1에서 볼 것 (판정 조건 제안 `[가정]`)

- S4_comp vs S4_coop 산포: 두 값의 **상관이 낮고**(독립 축처럼 행동),
- **협동 우세 프로필이 실존**하며(5~8개 중 1개 이상),
- 그 프로필이 현행 단일 경쟁소셜형 규칙으로 **오분류·미분류되는 사례가 확인**되면 → 분리 후보 강화.
- 반대로 멀티 시간이 대부분 MIXED에 떨어지거나 협동 우세 프로필이 안 잡히면 → 5종 유지 + "협동" 보조 태그로 처리(소프트 코어 모델의 보조 태그 슬롯 활용).

## §5 열린 항목·한계

1. **게임→대륙 배정 사다리 `[미정]`** — 한 게임이 여러 대륙 태그를 가질 때(호러 RPG, 로그라이크 덱빌더 등) 시간을 어느 대륙에 줄지 규칙 필요. 제안: **특수 대륙 우선**(메트로배니아·로그라이크·대전격투·FPS·호러·퍼즐 > 레이싱·시뮬·전략·RPG > 어드벤처·액션 우산) — 상위 20 태그 중 사다리 최상위 히트 1개에 전량 배정 vs 가중 분할, M1에서 비교.
2. **S3(장르 집중도) 재정의 필요** — 잡식가 넓이 카운트는 원태그가 아니라 **대륙 매핑 후** 세어야 우산 태그 부풀림(액션·어드벤처)이 보정된다. 배정 사다리(항목 1)가 선행 조건.
3. **위성 배정의 `[가정]` 다수** — MOBA→전략, MMORPG→RPG, TPS→FPS슈팅, Automobile Sim→레이싱 등은 판단 배정이다. M1 실프로필에서 위화감 나는 배정을 교정.
4. **태그 품질 편차** — 태그는 커뮤니티 산물로 게임별 신뢰도가 다르고, 상위 20개만 노출·가중된다[검증 — Steamworks 문서]. 21위 이하 태그는 조작화에서 보이지 않는다.
5. **서드파티 수치 의존** — 게임 수 카운트(SRec·stmstat)는 Valve 공식 통계가 아니다. 규모 감각·방향 근거로만 쓰고 수치 자체를 스펙에 옮기지 않는다.
6. **모드별 플레이타임 부재** — 하이브리드 게임의 캠페인/멀티 시간 분해는 공개 데이터로 불가(§3.4). MULTI_MIXED의 크기가 이 한계의 측정치가 된다.
7. **임계값 전부 잠정** — S4_comp ≥ 35~40%, 완주자 보정 방식, MIXED 산입 비율 등은 M1 실측 전까지 `[가정]`/`[미정]`.
8. **언어 기준** — 태그는 스토어에서 로컬라이즈되어 표시되지만 조작화·매칭은 영문 태그명 기준으로 고정한다.
9. **12대륙 세트 자체는 이 문서의 입력** — 대륙 구성(왜 12개, 왜 이 12개)의 타당성 재평가는 M2 범위 밖(목업 v3 확정 사항).
