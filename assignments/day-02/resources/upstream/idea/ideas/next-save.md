## 1. 한 줄 요약
이미 산 Steam 백로그에서 **"다음에 뭘, 왜"를 근거와 함께 추천**하고, 그 기록으로
**"나는 어떤 플레이어인가"(정체성 서사)** 를 만드는 서비스. 구매가 아니라 **소화**를 돕는다.
(경쟁 트래커에 없는 **설명가능 추천 + 정체성 서사 = 지능층**이 wedge.)
🆕 **랜딩 1차 약속(결정1=B안, 2026-07-08):** 히어로는 백로그 유틸리티 우선 — "YOUR GAME BACKLOG, FINALLY MAKING SENSE" → 정체성·추천이 payoff, 커뮤니티는 그 아래 기둥. 감정·공유는 히어로에 안 태움(§6 리스크 회피).
🗺️ **코어 Aha 확정(2026-07-09, 확정 대체):** 정체성 payoff = **취향 지도(장르 대륙 정복·탐험) + 아키타입 도감(2축 4종)**. "나는 어떤 플레이어인가"를 정적 서사 카드가 아니라 **정복해가는 지도 + 판정된 아키타입**으로 보여줌. 톤 = 죄책감·허영 아닌 **탐험·모험**(경쟁자 Backlog Shuffle 낭비액·Slayer 랭크와 정반대). 시각화 = `next-save-taste-atlas.html`.

## 2. 문제
- 누구의 문제인가: 세일마다 사서 라이브러리 100~500개인데 **"뭘 할지" 막막한** 공개 프로필 Steam 게이머.
- 얼마나 아픈가: Steam 추천은 *왜* 미는지 안 알려주고, 기존 트래커는 **수백 개를 손으로 넣어야** 시작됨(마찰). `[가정: 통증 강도 외부검증 안 됨]`
- 얼마나 자주 겪나: 세일·신작 때마다 반복 `[가정: 빈도 정량 미확인]`
- **[검증] 실제 사람에게 확인했나?** `부분` — **추천 수요**는 창업자 본인 통증(n=1, 내부 신호뿐). **가장 위험한 축 "공유 갈증"(§6)은 외부 신호가 아직 없음.** → §6.5 게이트로 직접 겨냥한다.

## 4. 핵심 가치 / wedge
경쟁(KTOMG=배관 통합, Backloggd=소셜 로그, SavePoint=기분필터 결정지원)은 **학습형 추천/설명/서사가 없다.**
이 빈자리 + 창업자의 RecSys/ML 배경 = **비대칭 = 지능층.**
⚠️ **비대칭 약화(§10 접지):** Backlog Coach·Backlog Shuffle이 이미 Steam 연동 AI 추천을 함 → "유일"은 과장.
살아있는 차별점은 **설명 충실성 + 정체성 서사**로 좁혀야 함. `[가정: 좁힌 차별점이 실제로 방어 가능한지]`

## 5. 핵심 시나리오 & 사용자 여정
**유즈케이스 (≤3):**
1. **[UC-1 정체성]** 게이머가 Steam URL을 붙여넣으면 → *수동 입력 없이* 플레이 이력에서 뽑은 "게이밍 페르소나 + 올해의 여정"을 즉시 본다.
2. **[UC-2 근거 추천]** 백로그(안 한 것·하다 만 것) 중 *"이걸, 지금, 왜"* 가 붙은 추천 3~5개를 받고, 각 근거를 자기 이력에서 확인한다.
3. **[UC-3 아틀라스 스냅샷]** 취향 아틀라스(지도+아키타입)를 **공유용 정적 스냅샷 이미지**로 렌더(공유·내보내기 배관은 v0에서 컷 — §7). 공유 수요는 §6.5에서 별도로 잰다.

**Happy path 여정 (컷 반영):**
1. **도착** — 랜딩 입력창 하나 "Steam URL 붙여넣기". 가입·설치 없음.
2. **수집(SYS)** — 공개 API로 보유·플레이타임·업적률 수집, "네 라이브러리 읽는 중" 진행 표시.
3. **AHA — 정체성 공개** — 어떤 플레이어인지 + 올해의 여정이 한 화면에. `[가정: 이 형태가 최적 Aha인지 미정 — 사용자曰 "달라질 수 있음"]`
4. **다음 픽** — 백로그 근거 추천 3~5개, 각 "왜" 펼침. ← **데모의 심장(설명 충실성)**.
5. **정적 스냅샷** — 취향 아틀라스를 공유용 정적 이미지로 렌더(로그인·공유·내보내기 없음 — 컷).

🆕 **랜딩 IA 확정(5블록, 2026-07-08):** 히어로(유틸 우선) → How it works → 정체성(취향 아틀라스) → Next Picks → **커뮤니티(게임별 페이지 + 리뷰 레이어)**. 게임별 페이지 = 공개 데이터로 진짜(게임단위 평균 시간·도전과제%), **객관 숫자 크게 + 개인화 해석 필수 곁들임**('느린 HLTB' 방지선). '너 같은 사람들'·우리 유저 카운트 = v0 제외(coming soon, B단계).
🗺️ **Aha 형태 확정 = 취향 지도(2026-07-09):** §5 step3 "정체성 공개" + UC-1/UC-3의 구체 형태 = **장르 대륙 지도가 플레이 이력으로 그려지고(3단계 채색) → 아키타입 판정 → 대륙 클릭하면 그 장르의 추천 게임 설명 모달 → 진행 CTA**. 기존 "정적 정체성 카드"는 별도 산출물이 아니라 **취향 아틀라스를 공유용으로 정적 렌더한 스냅샷**으로 재정의(아틀라스가 본체·상위 프레임, 스냅샷은 그 사진 한 장). 인터랙션: 섬/범례/프론티어 클릭 → 신호접지 "왜" + HLTB 시간 + "시작하기". 목업 = `next-save-taste-atlas.html`(v3).

## 🔒 6. 가장 위험한 가정
**공유 갈증(표현 수요) — 사람들이 자동생성 아틀라스 스냅샷을 실제로 남에게 공유·표현할 것인가.**
PRD가 이를 "핵심 신호"라 부르지만 뒷받침 근거는 **아직 없다.** (§10의 Backloggd 65만은 *수동 로깅* 표현 수요 — *자동생성 ML 아틀라스* 공유 수요와 다름. 차용 증거.)

**리스크 Top 3** (1번 = 위 가정):
1. **공유 갈증 미검증** — 표현 수요가 없으면 정체성 서사·공유 루프 전체가 성립하지 않는다. `[가정]` → §6.5로 겨냥.
2. **실행·범위 리스크** — 성공=데모 완성도인데 유한한 시간에 코어를 인상적 완성도로 뽑나. (컷으로 폭↓, 그 예산을 깊이로.)

## 부록 A. 기능요구(FR) · 데이터 신호 — `archive/…/prd.html` v0.1 흡수 (아틀라스로 번역)
> v0 **데모 목업** 빌드의 뼈대. 옛 "정체성 카드" 산출물은 "취향 아틀라스/스냅샷"으로 번역. 데모는 하드코딩 예시 데이터 위에서 이 흐름을 렌더(진짜 연동 아님 — §7). R5/R6 결정과 정합(리뷰 제외, HLTB=게임단위 공개).

**기능요구**
- **FR-1 Steam 프로필 수집 (MUST)** — URL/vanity → SteamID 해석 + 공개 프로필 검증(비공개면 안내). `GetOwnedGames`(보유·플레이타임) + `GetPlayerAchievements`(완주 근사). AppID → IGDB 매칭으로 장르·태그·메커닉 피처. *(데모=사전계산 룩업 테이블 대체 가능.)*
- **FR-2 추천 엔진 retrieval+rerank (MUST)** — 백로그(미플레이·중단) 콘텐츠 유사도 retrieval → 개인 신호(선호 태그·완주·플레이타임 가중)로 rerank → **각 추천에 해석 가능한 근거 신호**를 함께 출력(→ FR-4 입력).
- **FR-3 취향 아틀라스 생성 (MUST)** — 신호 S1~S5에서 **아키타입 소프트 코어 5종**(주 코어+강도%+보조 태그+개인 근거 — 2026-07-20 결정 A) 도출 + 장르 대륙 3단계 채색(미개척/탐험중/정복) + 공유용 **아틀라스 스냅샷**.
- **FR-4 LLM 근거화 · 충실성 규율 (MUST)** — 입력은 원시 임베딩이 아니라 **해석 가능한 신호**(태그 클러스터·시간·완주). 출력은 신호를 넘는 주장 금지("설명 극장" 차단).
- **FR-5 공유·계정 = 컷** — v0 미빌드. 정적 아틀라스 스냅샷 이미지로 대체, 공유 수요는 §6.5 $0 게이트로만 측정.

**데이터 신호표**

| 소스 | 주는 것 | v0 용도 / 주의 |
|---|---|---|
| `GetOwnedGames` | 보유 · 게임별 플레이타임 | 백로그 분류 · rerank 가중 — 소지≠플레이 |

| IGDB | 태그 · 장르 · 메커닉 | 콘텐츠 피처 · AppID 매칭 필요 |
| (게임단위 공개) HLTB · Steam 글로벌 업적% | 평균 클리어 시간 · 전역 난이도 | 게임 페이지 객관 숫자 — **개인화 해석 곁들임 필수**('느린 HLTB' 방지) |

**비타협 규율:** 플레이타임은 노이즈 라벨(방치·번들·미실행). 신뢰 훼손을 막기 위해 **업적 완주율을 "좋아함" 신호로 우선**하고, 근거는 반드시 실제 신호에 붙인다. 자신만만하게 틀린 근거는 근거 없는 추천보다 나쁘다. **game-level(게임 단위 평균) ≠ player-level(개인 성향) 혼용 금지**(Codex 가드).
