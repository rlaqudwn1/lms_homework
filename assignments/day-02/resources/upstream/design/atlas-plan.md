# 003 · 취향 아틀라스 A/B 하이브리드 — 중간 점검 기획서 (v0.9-plan)

> 📌 이 문서 = `direction.md` v0.9(결정 장부)의 **실행 계획 부속서**. 도메인 분해 + 조사 방안 + 진행 옵션. 실제 검색·생성은 여기 없음(계획만). 2026-07-20 중간 점검(서브에이전트 정리 + 오너 확인).

**TL;DR** — 아틀라스는 확정됐다(연륙 단일 대륙 + A/B 하이브리드: **데이터가 지형을, 픽셀 모티프가 장르 인식을**). 지금 필요한 건 그림이 아니라 **넘길 스펙**이다 — 이 문서는 (1) 아이디어를 컴포넌트·하위문제로 쪼개고, (2) 각 하위문제를 어떤 채널로 어떻게 조사할지 계획하고, (3) 지금 착수 가능한 3~5개 옵션을 의존성과 함께 세운다.

> **현행 구현 실측(atlas.tsx 확인):** 색 = teal 3티어 고도(`claim`/`explore`/`unchart`) + frontier=violet, 장르 = 손으로 찍은 심볼 스프라이트 12종(`SPRITES`), 배치 = **cx/cy 수동 하드코딩(=흩어진 군도)**, 음영 = 해안 BFS depth + 체커 디더. 상호작용(hover→RecCard, click→modal, 양방향 하이라이트)은 이미 견고. → **바뀔 것은 "배치·연결·모티프 승격"이지 상호작용·색규율이 아니다.**

## 1) 도메인 분해 (Domain Decomposition)

### (a) 페이지 컴포넌트 층위 — 각 컴포넌트의 디자인 문제 1줄

| 스파인 | 컴포넌트 | 디자인 문제 (미해결 한 줄) |
|---|---|---|
| S0 | DemoBar (정직 배너) | 조작 아닌 "예시" 고지를 무대감 안 깨고 상단에 다는 법 (taste #3) |
| S1 | Nav | 에디토리얼 절제 헤더 — 크롬이 무대와 안 싸우게 |
| S2 | **Hero** | 우측 공백(기지 문제): 첫 화면에 시그니처(대륙)를 어떻게 예고할지 |
| S3 | ProfileStrip | 예시 프로필 3스탯을 카드 남발 없이 라인/밴드로 (taste #4) |

| **S5·S6** | **★ Taste Atlas (시그니처)** | 군도→연륙 대륙 전환 + 데이터↔삽화 하이브리드 확립 (본 문서 핵심) |
| S7-b | Trend games | 스토어 그리드를 웜 없이 쿨 무대에 앉히기 (커버=콘텐츠 웜만 허용) |

| — | **배경/무대 (전역)** | flat ink에 웜 없이 깊이 주기(좌표 그리드 워시) — 아틀라스와 한 재질로 통일 |
| — | 토큰 (색·타입·모션) | 아틀라스 3색(teal 고도·violet 변방)이 페이지 크롬과 격리 유지되나 |

### (b) 아틀라스 내부 하위문제 층위 (이번 핵심) — 무엇이 미해결인가

| # | 하위문제 | A/B 역할 | 미해결 (지금 구멍) |
|---|---|---|---|
| ① | **대륙 형태 생성** (데이터→지형) | **A** | cx/cy가 **수동 하드코딩**이라 인접이 데이터에서 안 나옴. 지협·연결·전체 실루엣이 없음. "지도가 매번 안 바뀌게" 하는 결정론적 규칙 부재 |
| ② | **장르 모티프 어휘** (12장르 인식) | **B** | 스프라이트는 있으나 "심볼 아이콘"이지 **biome로 승격 안 됨**(질감·해안·내부 패턴 없음). 약한 3종(퍼즐·FPS·격투) 판독 실패. 대륙에 박히면 심볼이 뭉갬 |
| ③ | **색·고도 인코딩** (정복도/보유량/변방) | A→B | 현재 1변수(playtime=teal 명도)만. 보유량(넓이) vs 정복도(밝기)를 **동시에** 정직하게 인코딩하는 규칙 미정. 웜 복귀 금지선(taste #2)과 충돌 없이 |
| ④ | **상호작용** (땅 클릭→추천) | — | 모델은 견고. 단 **연륙 대륙에서 "땅 하나"의 히트영역·경계**가 군도보다 모호 → hover 타겟팅 규격 재설계 필요 |
| ⑤ | **모바일/라벨 규격** | B | 라벨 스케일 판독 불가(감사 위반 #6 잔존). 12땅 라벨이 좁은 폭에서 겹침 — 경계/모티프가 라벨 의존을 줄여야 |
| ⑥ | **배경/무대와의 통일** | B | 대륙이 "섬처럼 고립"된 느낌. 배경 좌표 그리드가 같은 언어로 확장돼야 패치워크 방지 |

**형태 결정론 4레버(스케치 `continent-character` 참고):** ①중심질량=핵심 취향, ②곶 넓이=보유·플레이시간, ③고원 밝기=마스터도, ④변방 흐림=미개척. "다 넣으면 과함" — 이 중 무엇을 살릴지가 ①③의 열린 결정. (오너 추천 채택: **②넓이·③밝기·④변방 3개**, ①심장부는 넓이의 창발.)

**설계 원칙 (2026-07-20 추가) — 안정적 진화(Stable Evolution):** 결정론 = "정지"가 아니라 **"안정적 진화"**. 고정 그래프가 자리·이웃을 고정 → **정체성 유지**. 데이터가 자라면(플레이·보유·정복↑) **크기·밝기만** 자라고 **미개척 변방이 개척지로 전환** → 계정 발전 시 대륙이 "같은 내 대륙인 채로 성장". 리렌더 트리거 = **데이터 스냅샷 변화 시**(=성장 반영), 매 새로고침 아님. 개인화도 여기서 나옴(같은 규칙 × 다른 라이브러리 = 다른 대륙). 시각 실증 = Artifact `atlas-howitworks` §진화(지금 vs 3개월 뒤). ← 이 "성장 loop"는 리텐션(돌아와서 내 대륙 자란 것 확인) 후보이기도 함, 별도 검토.

> **트랙 격리 (오너 2026-07-20 "다른 문제로 가자"):** 하위문제 ②"각 땅을 **라벨 없이** 그 장르로 인식"은 **별도 우선 트랙**으로 다룬다. 현행 렌더는 아직 라벨·작은 심볼 의존 → 이걸 biome 모티프 승격으로 해소하는 게 옵션 A의 핵심 절반이자 독립 작업.

## 2) 조사 방안 (Research Plan) — 하위문제별

> **채널 표기:** **Exa**=발견(레퍼런스·기법 존재 여부 탐색, neural search) · **WebSearch**=사실확인(특정 알고리즘/API 명세) · **Playwright**=브라우저 캡처(라이브 레퍼런스 실측) · (보조) **designlib**=팔레트/랜딩패턴 사내 소스.

### ① 데이터→대륙 형태를 **절차적으로** (핵심)
- **무엇을:** 12장르를 **하나로 이어진 픽셀 대륙**으로 배치하되, 유사 장르가 지협으로 붙고, **같은 입력이면 같은 지도**가 나오는 결정론적 규칙.
- **각도(키워드):** `metaball / marching squares blob`, `Voronoi region map procedural`, `cellular automata cave→island`, `force-directed graph layout deterministic seed`, `Whittaker biome adjacency diagram`, 레퍼런스: *Map of the Internet(원형 영역)*, *lars-janssen Map of Video Games(아이콘→대륙)*.
- **좋은 답:** (a) **고정 인접 그래프**(장르 유사도 → 이웃 확정) (b) 결정론적 시드(SSR/hydration 안정, 현행 `RENDER` 모듈로드 계산과 호환) (c) 단일 실루엣 + 지협 (d) 데이터 0인 장르도 "곶/변방"으로 붙되 대륙에서 안 떨어짐.
- **채널:** **Exa** → **WebSearch**(marching squares/Voronoi 구현 명세) → **Playwright**(lars-janssen·Halcyon 컴포넌트 캡처).

### ② 장르 픽셀 모티프 12종 **정의·제작**
- **무엇을:** 각 장르-땅을 **라벨 없이 2초 안에** 그 장르로 인식시키는 픽셀 모티프 어휘. "심볼 아이콘"→"biome(질감+해안+내부 패턴)" 승격.
- **각도:** `pixel tileset biome grammar`, `Wang/blob tiles 47 autotiling`, `RPG overworld tileset biome color motif`, 레퍼런스: *Pixel Cartography 타일셋*, *RPG Overworld Tileset(6 biome)*.
- **좋은 답:** (a) 12장르 각각 = **biome 사전 1엔트리**(대표 모티프 + 해안 처리 + 내부 디더 규칙) (b) 약한 3종(퍼즐·FPS·격투) 재도트 (c) 쿨 단일 팔레트 안에서 성립(웜 0) (d) 심볼→biome 승격이 대륙 연결과 충돌 안 함.
- **채널:** **Exa** → **Playwright**(타일셋 컴포넌트 캡처).

### ③ 색·고도 인코딩 (정복도/보유량/변방)
- **무엇을:** 넓이(보유량)·밝기(정복도)·변방(미개척)을 **동시에 정직하게** 인코딩(실측 일치, taste #1).
- **각도:** `hypsometric tint elevation encoding`, `single-hue sequential ramp accessibility`, `dithering depth banding`. designlib `list_palettes`(쿨 시퀀셜).
- **좋은 답:** (a) teal 단일 hue 시퀀셜 3티어+ 구분 & WCAG 대비 통과 (b) 넓이=데이터·밝기=정복도 이중 인코딩이 안 헷갈림 (c) **웜 복귀 없음**(taste #2, v0.6 "맵도 쿨 단일" 유지).
- **채널:** **designlib** → **WebSearch**(hypsometric/색각 접근성).

### ④ 상호작용 (땅 클릭→추천패널)
- **무엇을:** 연륙 대륙에서 "장르 영역" 히트영역·포커스링·경계 강조 규격(현행 `ns-px-hit` rect가 군도 전제).
- **좋은 답:** 경계선 하이라이트로 "이 땅" 명확 · 포커스 외곽 ≥2px/3:1(playbook W3) · 겹친 지협에서 타겟 안 샘.
- **채널:** **WebSearch**(SVG 영역 인터랙션 패턴).

### ⑤ 모바일/라벨 규격
- **무엇을:** 좁은 폭 라벨 겹침 해소 — **경계·모티프가 라벨 의존을 대체**.
- **각도:** `map label placement collision mobile`, `responsive SVG viewBox scaling`, `icon-only legend`.
- **좋은 답:** 라벨 없이도 biome로 장르 짐작 · 탭 타겟 ≥24px(playbook W1) · 라벨은 활성 땅만.
- **채널:** **WebSearch** → **Playwright**(모바일 뷰 실측).

### ⑥ 배경/무대 통일
- **무엇을:** 페이지 배경을 아틀라스 좌표 그리드·경위선으로 아주 흐리게 확장 → 한 은유로 묶기, 웜워시 0.
- **좋은 답:** 깊이 생김 + 온도 리스크 0 + 고립감 완화 · 그라디언트 마스크+비네트 **동시 금지, 하나만**.
- **채널:** **designlib** → **Exa**(카토그래피 워시 레퍼런스).

### 특별 조사 — 이 스펙을 **Claude Design / Pencil에 어떻게 넘길지**
- **무엇을:** 생성기 두 종이 **소화 가능한 스펙 형태** — 토큰(색·고도 램프) + 규칙(인접 그래프·biome 사전) + 예시 이미지.
- **좋은 답:** 스펙만 주고(원본 비노출, 익명화 규율) 생성기가 "장르가 읽히는 연륙 대륙"을 뽑음. Claude Design vs Pencil 나란히 A/B.
- **채널:** **Pencil MCP**(`get_guidelines`로 수용 스펙 형태 확인 → `batch_design`) · Claude Design은 스펙 프롬프트. **먼저 get_guidelines를 읽어 스키마를 맞춘다.**

## 3) 진행 방안 (Actionable Options)

> 개념 스캐폴딩: "스펙을 넘긴다"=우리가 그림을 그리는 게 아니라, **생성기가 따라 그릴 수 있는 규칙서(토큰+인접그래프+biome사전+예시)를 만든다**는 뜻.

### ★ 옵션 A (강력 추천) — "12장르 모티프 어휘 + 인접 그래프" 스펙부터 확정
- **선행조건:** 없음(현행 `SPRITES`·`ISLANDS` 데이터가 출발점).
- **산출물:** `atlas-spec` 초안 = ①12 biome 사전(장르→모티프·해안·디더) ②장르 유사도 → **고정 인접 그래프** ③색·고도 램프 토큰.
- **리스크:** biome 승격이 픽셀 해상도 문법과 충돌(회화적 음영 금지선). 약한 3종 재도트 필요.
- **왜 먼저:** 어휘가 서야 생성기가 뭘 그릴지 안다. 없으면 A/B가 허공에 쏨. **임계경로 — 다른 옵션의 입력.**

### 옵션 B — 절차적 형태 생성 조사 스파이크 (A와 **병렬 가능**)
- **선행조건:** 없음(순수 리서치, 코드 0). **산출물:** 기법 비교 노트(metaball vs Voronoi vs 고정그래프+오프셋) + 성공기준 판정.
- **리스크:** 과도한 절차생성 = "매번 바뀌는 지도"(신뢰 훼손). 고정 이웃이 답일 가능성 높음. **의존성:** A의 인접 그래프를 입력받으면 최적.

### 옵션 C — 생성기 A/B 첫 시도 (Claude Design vs Pencil)
- **선행조건:** **옵션 A 산출물 필수** + Pencil `get_guidelines` 선독. **산출물:** 동일 스펙 → 두 산출 비교 보드(장르 인식률·연륙감·쿨단일 준수 3기준 채점).
- **리스크:** 스펙 얇으면 둘 다 실패 → A 품질이 게이트. 익명화 규율. **A 확정 후 착수 권장.**

### 옵션 D — 배경/무대 통일 + Hero 티저 (저리스크, 전 구간 병렬)
- **선행조건:** 없음(현행 CSS, taste #2 웜 0 규율 명확). **산출물:** 좌표 그리드 워시 배경 스펙 + Hero 우측 "대륙 조각" 정적 티저.
- **리스크:** 낮음. 단 대륙 최종 형태 확정 전 티저 확정하면 재작업. **왜:** 시그니처 리스크 없이 "고립감·히어로 공백"(v0.7 최대 지적) 즉시 완화.

### 옵션 E — 상호작용·모바일 규격 재설계 (후행)
- **선행조건:** A+B 수렴(연륙 형태 확정) 후. **가장 마지막** — 형태 미확정 시 전면 재작업.

**추천 실행 흐름:** `A(+B 병렬) → C → E`, `D`는 전 구간 병렬. **A가 임계경로.**
