# design-needs.md — 디자인 → 기획(PRD/대본)에 요청하는 것

> 이 레포는 **디자인·UI/UX만** 다룬다. 아래는 UI/UX가 자연스럽게 "무엇을 할 수 있고 / 무엇을 얻는지"를 말하려면 **기획(`idea` 프로젝트)에서 확정해줘야 하는 입력**들이다. 각 항목 = [무엇이 필요] + [왜(어느 UI가 이걸 먹음)] + [지금 쓰는 placeholder].
> 디자인은 이게 채워지면 대부분 자연히 정리된다. 지금 다 정할 필요 없음 — ★가 가장 먼저 필요한 것.

---

## ★ 결정 1 — 히어로의 1차 약속: 정체성 vs 백로그 유틸리티 (가장 중요)
지금 히어로는 **정체성 카드(Aha) = "이게 곧 너다"** 를 주연으로 세웠다. 그런데 이 제품은 **게임 백로그 도구**(analyze your backlog / 뭘 다음에 할지)이기도 하다. 히어로가 뭘 먼저 약속하느냐가 헤드라인·서브카피·카드 배치를 전부 결정한다.

- **선택지 A — 정체성 우선:** "너의 게이밍 정체성"이 미끼, 백로그 유틸은 아래에서 설명. (지금 상태) → 감정·공유 강함, 유틸 가치가 늦게 전달.
- **선택지 B — 유틸리티 우선:** "네 백로그를 분석해서 뭘 할지 알려줌"이 헤드라인, 정체성 카드는 "얻는 것"의 증거로. → 실용 가치 즉시 전달, 감정 미끼 약함.
- **선택지 C — 이중 약속:** 헤드라인이 백로그 유틸을 명시 + 카드가 시각 앵커. (디자인 추천 — 카드는 앵커로 두되 카피가 "job"을 말함)

**기획이 정할 것:** 이 랜딩의 **1차 약속 한 문장**. (예: "너의 백로그를 이해하고, 뭘 할지 알려주고, 공유할 카드를 준다" 중 무엇이 먼저인가.) → 이게 있어야 헤드라인이 "gaming identity"에 머물지, "backlog"를 말할지 정해진다.

## 슬롯 1 — 제품 한 문장 & "backlog" 명시
- **필요:** 이 제품이 뭔지 한 문장 + "게임 **백로그**"라는 단어가 어디서 나올지.
- **왜:** 지금 헤드라인("YOUR GAMING IDENTITY, RECEIPTED")엔 "backlog"가 없다. 유저가 "이게 백로그 도구구나"를 언제 아는지가 안 잡혀 있음. How it works나 서브카피에서 명시돼야.
- **placeholder:** "One link in. Out comes an explained backlog…" (서브카피에만 살짝 있음)

## 슬롯 2 — 무엇을 할 수 있는가 (기능 = Do)
- **필요:** 유저가 이걸로 하는 **핵심 액션 2~3개**의 정식 이름·설명. (예: "뭘 할지 3개 추천받기 / 백로그 점수 보기 / 정체성 카드 내보내기?")
- **왜:** "신뢰(추천)" 섹션과 카드가 이걸 시각화한다. 지금은 추천 3장 + 카드뿐 — 기능 목록이 기획에서 확정되면 섹션이 정확해짐.
- **placeholder:** 추천 카드("Outer Wilds — 94% fit"), 정체성 카드. SavePoint식 "Decision Engine / Backlog Score / Year in Gaming" 같은 명명이 있는지?

## 슬롯 3 — 무엇을 얻는가 (성과 = Get)
- **필요:** 유저가 얻는 **결과물**의 정의. (설명가능한 추천 / 공유 카드 / 백로그 정리 — 각각 뭐라 부르나)
- **왜:** "공유" 섹션·정체성 카드가 이 "얻는 것"을 판다. Do(기능)와 Get(성과)를 기획이 구분해줘야 카피가 안 겹침.
- **placeholder:** "explained backlog + a card worth sharing"

## 슬롯 4 — 진짜 계산 가능한 숫자 (receipts 진실성)
- **필요:** Steam 공개 데이터로 **실제 계산 가능한 지표 목록**. (플레이시간·완주율·업적률·장르 분포·연간 시간… 어디까지 진짜?)
- **왜:** receipts 섹션·카드가 "22% vs 중앙값 9%", "340 hrs", "1049/068/040"을 보여주는데 **전부 placeholder**다. 바넘금지 규율상 실제 계산 가능한 것만 UI에 넣어야 거짓말이 안 됨. (관련: 이미 랜딩에 How it works로 "플레이시간·완주·업적 읽음" 명시함)
- **placeholder:** 2,140 hrs / 22% 완주 / 1049·068·040 / 장르 42·28·18% — **전부 가짜**.

## 슬롯 5 — 추천의 "왜" 로직 (해자 카피)
- **필요:** 추천에 붙는 **근거 문장의 실제 규칙**. ("소울류 3편 100% 클리어했으니" 같은 근거를 진짜 어떤 데이터로 만드나?)
- **왜:** "근거 붙은 추천"이 이 제품의 차별화(해자)인데, 근거 문장이 진짜 로직에서 나와야 신뢰가 산다. 지금 문구는 내가 지어냄.
- **placeholder:** "You 100%'d 3 metroidvanias this year", "92% of players like you finished it".

## 슬롯 6 — 이름 (제품명 · 플레이어 타입)
- **필요:** ① 제품명(현재 "NEXT SAVE" 가제) ② 정체성 카드의 **플레이어 타입 라벨**이 실제 기능인지("THE COMPLETIONIST" — 유형 분류를 진짜 하나?).
- **왜:** 워드마크·카드 헤더가 이걸 씀. 타입 분류가 기능이면 카드 설계가 커지고, 아니면 뺀다.
- **placeholder:** "NEXT SAVE", "THE COMPLETIONIST".

## 디자인이 지금 스스로 정리하는 것 (기획 입력 불필요)
- 색·폰트·글로우·온도·간격·반응형 = 계속 조정. (큰 방향 OK)
- 정체성 카드의 시각 형태·데이터 밀도 = 프로토타입으로 계속 다듬음.
- 위 슬롯이 채워지면 → 헤드라인/섹션 카피 교체 + 카드에 실제 지표 연결만 하면 됨.

## 한 줄 요약 (idea로 가져갈 것)
**"1차 약속 한 문장(결정1) + 실제 계산 가능한 지표 목록(슬롯4) + 추천 근거 로직(슬롯5)"** — 이 셋만 오면 디자인이 "무엇을 하고 무엇을 얻는지"를 자연스러운 UI/UX로 완성한다.
